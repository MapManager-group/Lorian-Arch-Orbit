# 向下迁移指南（面向 AI）

用于把 `26.2/` 回移到 `26.1.x`、`1.21.11`、`1.21.1` 等旧版本。每个目标都从用户手动下载的对应版本 Architectury Mod Template 开始，不能把 26.2 工程降级依赖后直接使用。

## 强制流程

1. 完整阅读根规范与本指南，锁定一个目标 Minecraft 版本和目录。
2. 审计新旧模板的 Java、Gradle、Loom、映射、Loader、Fabric API、Architectury、NeoForge及依赖可用性，形成 Migration Plan 并等待用户批准。
3. 先构建原始旧版模板，确认它在指定 JDK 上可用。旧版 Minecraft 可能要求 Java 21 或更低；以模板和官方版本要求为准，不强行沿用 JDK 25。
4. 优先移植无 Minecraft 依赖的配置、Feature、状态机和算法，再逐平台恢复功能。每完成一项就编译和测试，不一次性复制全部源码。

## 旧版适配重点

- 映射可能从无混淆官方名切换为 Yarn 或其他命名空间；所有导入、方法名、字段名和 Access Widener 必须以目标 Loom 为证据。
- Architectury 网络、客户端事件、按键注册、配置入口和模型修改事件在旧版可能缺失或签名不同；分别查 Fabric/NeoForge 官方 API，不使用反射掩盖差异。
- 旧版物品数据可能使用 NBT 而非数据组件。色轮的“完整组件匹配”和分享 JSON 需要明确转换规则；无法无损转换时应拒绝导入并记录不兼容。
- 创造模式标签页、GUI 提取/绘制 API、HUD 矩阵和滚轮事件差异较大；编辑器必须在各 GUI 缩放下重新布局验收。
- 方块集合不同：删除目标版本不存在的默认成员，并依据该版本注册表补齐木材、石材、染色、铜及版本特有方块。测试不可引用不存在的 ID。
- 模型 JSON、图集、渲染层、BakedModel/quad API 和透明排序可能完全不同。墙、床、门及不可见方块需重新查目标模型，不应直接复制 26.2 Mixin 或资源覆盖。
- NeoForge 较旧版本可能仍使用 Forge 风格事件或不同元数据文件；以目标模板为准。

## 保持的契约

- 尽量保持 mod id、配置目录、翻译键、默认交互和发行文件命名一致。
- 交互距离仍由服务端授权；缺少所需属性或安全网络能力时，应禁用该功能而不是仅在客户端扩大命中。
- 若旧版无法读取 schema `2` 或分享格式，新增显式转换器或使用独立版本目录，绝不让旧版覆盖较新的配置。
- 客户端缺 Mod、服务端缺 Mod或协议不一致必须安全降级；专服不得加载屏幕、渲染或 YACL 类。

## 验证与交付

- 用目标目录 Wrapper 完整构建并核对两个发行产物、内部元数据和依赖范围。
- 启动双加载器客户端与专服；重点检查 Mixin 应用、网络注册、资源模型和配置热重载。
- 对目标版本实际存在的全部功能执行手工矩阵，并至少验证干净配置、来自 26.2 的配置副本、损坏 JSON、客户端/服务端混装和协议不一致。
- 更新目标目录 README、配置说明、迁移限制和 `UPDATE_NOTES.md`；列出因旧版 API/方块缺失而关闭的功能。
- 不把“编译通过”写成“运行时兼容通过”，未运行项目必须明确列出。
